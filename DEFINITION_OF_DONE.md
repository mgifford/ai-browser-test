# Definition of Done

This report is done when it is accurate, usable, reviewable, and ready to share publicly.

## Required outcomes

- The report states its purpose, audience, scope, and main question up front.
- The report includes a clear summary of findings, recommendations, or decisions.
- The report distinguishes confirmed findings from assumptions, open questions, or future work.
- The report has no placeholder text, unresolved TODOs, or missing sections.

## Evidence and traceability

- Material claims are backed by citations, links, or direct observations.
- Browser-specific findings identify the browser, version or channel, date, and test context when relevant.
- Any references to repository behavior align with the current implementation and documented feature set.
- External links are current and checked.

## Quality and readability

- The structure is easy to scan, with clear headings and concise sections.
- Language is plain, specific, and presentation-ready.
- Tables, screenshots, or examples are labeled and support the report's main message.
- Spelling, grammar, and formatting have been reviewed.

## Repository alignment

- Accessibility implications are considered and consistent with [ACCESSIBILITY.md](ACCESSIBILITY.md).
- Sustainability implications are considered and consistent with [SUSTAINABILITY.md](SUSTAINABILITY.md).
- Any implementation-specific statements stay aligned with current runtime behavior, probe outputs, and public documentation.
- If AI tools were used to help produce the report or related changes, the disclosure in [README.md](README.md) remains accurate.

## Review and approval

- The report has been self-reviewed for factual accuracy and internal consistency.
- At least one additional reviewer has confirmed the report is understandable and ready to publish or present.
- Any requested review changes have been resolved or explicitly logged.

## Ready to publish

A practical definition of done for this repository is:

- [ ] Purpose and scope are clear
- [ ] Findings are evidence-based
- [ ] Browser/runtime claims are dated and attributable
- [ ] Accessibility and sustainability considerations are covered
- [ ] Wording is polished and presentation-ready
- [ ] Links and references work
- [ ] Review feedback is resolved
- [ ] README disclosure remains accurate
